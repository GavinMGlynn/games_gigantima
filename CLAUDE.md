# Working conventions

## The shape of the thing

Gigantima is an **Ultima VI-style single-scale seamless world**. Towns and
dungeons sit in the same grid as the wilderness, at the same scale, with no
load screen and no scale change. Every design question resolves against that:
if a feature needs a separate map to enter, it is the wrong feature.

The **simulation is turn-based; the presentation is not.** The world advances
only inside `gg_game_act`. Animation, the camera and the day/night fade run at
60 Hz whether or not the world moved. Do not blur this line — a walk cycle that
advances the clock, or a turn that only happens when a frame is drawn, breaks
both halves at once.

## Discipline

- **`src/core/` is the simulation and must not know how anything is drawn,
  heard or typed at.** It may use SDL for portability — memory, files, logging,
  string formatting — but never a renderer, texture, window, event, gamepad or
  audio stream. This is checked at configure time by `cmake/Layering.cmake`, not
  remembered. `src/core/gg_ids.h` is the deliberate seam: generated from the
  art but carrying only the vocabulary, never a pixel coordinate.
- **Content is data, not C.** Maps, dialogue, creatures, quests and loot belong
  in files the editor writes and the game reads. The ambition is deep stories
  and a lot of levels, and that only works if adding content is not a code
  change. A hard-coded map is a prototype, and it must be replaced before it is
  built on.
- **Warnings are errors, in every build type.** `-Wconversion` and
  `-Wsign-conversion` included — they are the two that actually catch defects
  in a codebase this full of tile arithmetic. First-party targets only;
  vendored code in `ext/` is untouched.
- **Determinism is a feature.** The simulation is integer-only and seeded, so
  `--seed N` reproduces a world exactly. Never introduce floating point or
  wall-clock time into `src/core/`. A bug report is a seed and a turn count.
- **Verify on the real output.** A frame written by `--shot`, a `ctest` run, a
  screen recording — not a proxy, and not "it should work now". The camera bug
  that made the whole world lurch passed every test and was invisible in a
  screenshot; it took frames from a recording to see.
- **Measure before picking art.** `tools/scan_sheet.py` reports which cells of
  an LPC sheet can serve as ground. Do not choose a tile by looking at it: the
  sheets are 3×3 blob rings and the wrong pick has an edge or a hole baked in
  that only shows in a field of them.
- **One item at a time, landing with its test.** Keep `ctest` green; a red tree
  is the stop-everything condition. Name tests as sentences stating the fact
  they pin: `the_camera_moves_in_sub_tile_steps_while_walking`.
- **A test that only sometimes tests its rule is worse than no test**, because
  the green tick is not evidence. If a test depends on what the generator
  happened to produce, build the situation explicitly instead.
- **Commit each finished item and push.**
- **Every commit that lands an item updates both living docs in that same
  commit**: `docs/PROJECT_STATUS.md` (what now works, with its verification)
  and `docs/COMPLETION_PLAN.md` (tick the item, add any tails found while
  implementing it). Re-read both in full at every phase boundary — status docs
  rot fast.
- **A completed plan item is a summary; the balance moves to
  `PROJECT_STATUS.md`.** One line of what was done, its verification, and
  "Detail in `PROJECT_STATUS.md`". The plan is read forwards to choose the next
  thing; the status is read by whoever has to trust or change a subsystem.
- **Never describe a partial module as working.** "Working" means 100% of what
  it claims. Anything less is reported with the missing part named *first* —
  "the map format round-trips; there is no editor to write one yet", never "the
  map format works". If the answer to "is this done?" needs a qualifier, the
  qualifier is the honest report.
- **Regenerating the art regenerates the credits.** Attribution is a licence
  condition of OGA-BY, not documentation. `assets/CREDITS.md` is generated by
  the same script in the same run; they move together or not at all.

## This game's specifics

- **Tile size is 32 px and is not a free parameter.** The LPC Revised art is a
  32-pixel style. `GG_TILE` exists to name it, not to change it.
- **The camera is in pixels, never tiles.** A tile-quantised camera makes the
  world jump 32 px every time the player crosses a boundary, which reads as the
  game stuttering even though the avatar is interpolating perfectly. Pinned by
  `the_camera_moves_in_sub_tile_steps_while_walking`.
- **Held-movement repeat must not be faster than the step animation.**
  `GG_REPEAT_RATE >= GG_STEP_TICKS`, or a new move re-anchors the interpolation
  mid-slide and the sprite teleports backwards on every step.
- **A blocked move costs no turn.** Deliberately — otherwise a player starves
  by walking into a rock. Anything that loops "act until the turn advances"
  must therefore have a fallback and a bound; that exact bug hung a CI job.
- **Sort sprites by where they touch the ground**, in world pixels, props and
  actors in one list. Sorting by the top of a sprite makes a tall thing sort as
  if it stood a tile further back.
- **The debug window is a separate window**, not an overlay: the two things
  most wanted while debugging are the whole map and the normal view at the same
  time, and an overlay can only give one.
- **Prefer no dependency to a small one.** PNG decodes through stb rather than
  libpng precisely because libpng drags in zlib, and a system zlib advertising
  a static library it does not ship failed the configure with an error naming
  neither.

## Layout

```
src/core/       simulation — headless, deterministic, no SDL rendering types
src/gfx/        atlas textures, world renderer, bitmap font
src/ui/         title screen, status band, conversation panel
src/platform/   asset/save paths, keyboard and gamepad
src/debug/      the debug window
src/frontend/   one main.c per executable
cmake/          platform gate, warning set, layer check
tools/          art baker, sheet scanner
ext/            pinned submodules — see ext/README.md
docs/           COMPLETION_PLAN.md, PROJECT_STATUS.md
```
